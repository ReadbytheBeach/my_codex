# 主题中文标题

内容日期：YYYY-MM-DD（注明是讨论、存档或记录日期）。资料核查或证据截止日期未明确时保留未知。

**核心问题与结论：**说明要解决什么、当前结论是什么，以及成立条件。

此文件是模板。归档前替换占位内容，在 `notes/` 或 `docs/` 中保存真实主题，再到 `content-index.json` 登记永久编号、双语标题、主题、摘要和边界，由脚本生成阅读入口。

## 1. 背景与适用范围

写明来源、环境、版本与使用条件。用户提供的前提使用 `[USER_CONTEXT]`，不要推定未知配置。

## 2. 机制或操作过程

解释输入、输出、状态、依赖与反馈。命令示例标明适用环境，不把示例当作已执行记录。

## 3. 证据与验证

按具体命题区分 `[FACT]`、`[AUTHOR_REPORT]`、`[AUTHOR_HYPOTHESIS]`、`[DISCUSSION]`、`[PROPOSAL]` 与 `[LOCAL_RESULT]`。

如有实际结果，写明运行环境、时间、输入、产物与验证范围；没有结果就保留为方案。

## 4. 未解决问题与后续工作

记录已知限制、候选改动和明确的验收条件。

## 5. 来源与关联文档

列出实际读取的资料和真实关联。不要把占位链接或模板内容当作研究证据。
